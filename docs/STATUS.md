## M1 第二轮 · AWS/R2 可恢复上传

本轮分支 `feat/m1-resumable-upload` 基于上一轮浏览和下载提交 `aaf6fc2`。

| 能力 | 本轮行为 |
| --- | --- |
| 上传与重开 | 桌面原生文件选择器接受一个普通文件。Go 按完整 Key 上传。在任务中心可暂停和手动继续，SQLite v3 保存来源身份、会话和分片检查点。 |
| 恢复与校验 | 恢复时核对本地文件及服务端分片。只跳过双方均可核实的分片。完成前比较整个文件的 SHA-256，发布后核对远端长度及任务元数据。 |
| 冲突和取消 | 条件提交保护已经存在的同名对象。取消意图跨进程保存；已知未完成的会话可中止并检查清理结果。提交响应丢失时先核对该任务是否已经发布。 |

### 本轮验证与限制

- **执行通过**。两种客户端配置均在隔离的 Moto HTTPS 服务上传 24 MiB + 311 字节。子进程在远端接受第 3 片、本地写入该片检查点前被终止。测试另外改变远端第 2 片，重开后观测到仅第 2、3、4 片重传，独立读取完整对象后 SHA-256 匹配。
- **执行通过**。在完成分片请求抵达前写入一个竞争对象。两个客户端的条件提交均被拒绝，中止后查询特定会话得到 `NoSuchUpload`，独立读取确认竞争对象及其元数据完好。
- **执行通过**。Linux 生产 Wails 窗口通过系统凭据库存取测试身份。重开后通过 GTK 文件选择器下载已知对象，并上传 8 MiB + 37 字节的另一个文件。任务中心显示完成，独立的 Boto 客户端逐字节读回并核对摘要元数据；最终扫描未发现遗留的分片会话。
- **执行通过**。在本地 HTTPS 服务上分别以 AWS/R2 配置执行受限写入验收入口，核对一个 5 MiB 分片并确认中止。
- **执行通过**。锁文件安装、11 项前端测试、Vue 类型检查和生产构建。Chromium 验证中英导航、语言资源导入、取消准备时实际发送的 Wails 调用 ID，以及迟到响应不会中止已入队任务。
- **执行通过**。Go 模块校验、vet 和 6 个包的 54 项顶层测试。断网容器内的全包竞态检测通过。测试覆盖 v1/v2 数据迁移、源文件改变、空文件写入被拒绝、完成响应丢失、取消与完成争用，以及 SQLite 最终状态写入失败后恢复任务控制。
- **已修复并复验**。早期 GTK 自动化未选中源文件，桌面测试未通过；改为选中真实文件行后，原生上传与独立读回通过。Go 桥接测试在 SDK 更换传输层后失去隔离，现按测试实例注入传输，并在断网容器执行竞态检测。
- **执行失败并定位**。在 `32e3797` 的原生归档上，同时终止 Wails 和全部 WebKit 子进程曾使刚写入的语言偏好丢失。将应用退出与强杀传输进程分开验收后，5 个全新配置目录都在正常退出、重新打开时读回英语和连接记录。语言偏好依赖 WebView 落盘；强杀测试继续独立覆盖 SQLite 传输检查点。
- **未执行**。真实 AWS/R2 专用桶及整机重启验收。本实例未配置厂商测试桶与身份。Windows、macOS 的桌面交互需另行验证。
- **已知限制**。若服务已经创建会话，但进程在保存会话 ID 前中断，应用无法确认未知会话归属。此时保留不确定状态，由桶的过期分片生命周期规则清理。空文件 PUT 响应若丢失且远端持续不存在，也没有会话 ID 可据以中止；这时保留待核对状态。源文件摘要在入队前计算，停止准备可中断这次读取。自动重试及完整脱敏重试记录待开发。

实现提交 `8b67e84` 的 Windows amd64、Linux amd64、macOS arm64 和 macOS amd64 四个原生作业全部通过，已核对带完整 SHA 的四份产物与归档摘要。上传操作修复提交 `32e3797` 也已从云端 Linux 归档启动，经 GTK 文件对话框上传并独立核对对象字节。[初始实现构建及产物](https://github.com/Cdners/S3S/actions/runs/45598357667) · [操作修复提交的原生作业](https://github.com/Cdners/S3S/actions/runs/45598776418)

## M1 第一轮 · AWS/R2 浏览与下载（历史记录）

从 M0 提交 `9df19a5` 建立 `feat/m1-browse-download`。仓库包含可运行的 AWS SDK for Go v2 只读适配器、系统密钥库入口和 SQLite v2 下载引擎。

| 能力 | 本轮交付 |
| --- | --- |
| 凭据与浏览 | 每个连接显式保存或移除自己的密钥；SDK 固定目标 HTTPS 源。支持桶列表、手动打开指定桶、前缀和对象分页，保留 Key 的原始字符。AWS 使用厂商桶游标，R2 的桶按服务返回的名称在客户端分页。 |
| 下载与恢复 | 从原生保存对话框选择新目标。Go 用条件范围读取并持久化已确认区间和 SHA-256。暂停或异常退出后，任务中心可手动恢复；启动时先核对来源身份与临时文件。目标已存在时保留原文件。 |
| 兼容性 | M0 数据原地迁移；缺少远端身份的旧任务不能续传。Linux 密钥库需要可用的 Secret Service，下载目标文件系统需支持硬链接。 |
| 本轮边界 | 上传、复制、删除、自动重试策略、OSS/TOS、聚合限速、测速和 R2 选路仍在后续阶段。 |

- **通过**：Linux 云机上的 Go 模块校验、vet、27 项 Go 测试和实际 Linux 桌面编译。存储测试覆盖 M0 迁移、崩溃后重开、检查点冲突和异常文件处理。

- **通过**：Linux 真实 Wails/WebKit 窗口连接隔离的 Moto HTTPS 服务，并通过 GNOME Secret Service 保存临时凭据；结束进程并重开后列出桶及对象，使用 GTK 原生保存对话框下载，核对实际文件字节及已完成任务行。SQLite 文件检查未检出测试凭据。
