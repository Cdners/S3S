# 验证方法

普通拉取请求使用锁定依赖、临时数据库和内置语言资源。测试机无需配置真实云账号。每份验证记录写明提交 SHA、平台与架构、输入条件、实际执行的命令、退出状态及观察结果，填写到 [STATUS.md](STATUS.md)。使用“执行通过”“执行失败”“未执行”“跳过”区分结果，跳过须写明原因。

## 云端工程检查

在网页版 Codex 的云端工作区，从仓库根目录运行：

```sh
bash scripts/cloud-linux.sh setup
bash scripts/check.sh frontend
bash scripts/cloud-linux.sh run bash scripts/check.sh go
bash scripts/cloud-linux.sh run bash scripts/build.sh
```

浏览器验证使用云端已安装的 Playwright 1.62.0 和 Chromium，运行 `python3 tests/ui/preview.py`。执行 `bash tests/ui/linux-container.sh /path/to/S3S` 会用独立的临时配置，通过 AT-SPI 驱动 Xvfb 上的真实 Linux WebView，并重启程序检查本地记录。Docker 测试容器的限制及已执行结果见 [STATUS.md](STATUS.md)。

具有完整原生工具链的 Actions runner 依次运行 `bash scripts/check.sh` 和 `bash scripts/build.sh`。检查脚本及 CI 使用的参数见 [脚本目录](../scripts/)。分别检查以下行为：

- **核心与 SQLite**。使用真实临时数据库，从空文件迁移并重复打开，保存任务和分片，再关闭连接并重新打开，按身份核对内容。用带 `a//../b %25/文` 的 Key 检查往返结果。验证允许与禁止的状态迁移，以及失败操作不会留下部分状态。
- **S3 与下载**。签名、分页、Key 编码、条件范围响应和错误脱敏可用本地 HTTP 测试服务验证。用真实数据库及临时文件检查进程被终止后的精确续传区间、用户暂停、远端对象改变和本地目标冲突。凭据库单元测试检验连接范围与错误映射，操作系统服务交互需由桌面集成验证。
- **语言**。比较内置词典的全部 key 及各 key 的命名占位符。验证占位符可重排、缺失条目回退和无效语言包拒绝。新建原生控件时，同时添加对应菜单、托盘、通知资源并覆盖两种语言。
- **桌面交互**。在有图形会话的云端目标启动原生应用，访问四个页面，检查空列表和未接入提示，切换语言并核对重新启动后的设置。检查底层存储失败时显示错误，不显示空列表或成功提示代替失败。记录是否实际打开 WebView、触发操作和观察响应。
- **四平台构建**。检查对应 SHA 的四个原生 job 与产物，并核对归档内可执行文件或应用包及其架构。浏览器中的 Vue 验证、二进制格式检查和原生 WebView 交互各自记账。

在当前 Moto 场景中，测试子进程在远端已接收第 3 片、本地只有两个检查点时退出；另一个请求替换第 2 片。恢复后的实际写入必须为第 2、3、4 片，随后读回并校验完整对象。独立 Boto 客户端查询桶的分片会话，检查是否有遗留。

上传恢复验证要记录实际重传的分片编号、远端会话是否复用、完成后读回的文件摘要，以及取消后会话的消失。只看到本地进度达到 100% 不足以证明远端提交成功。

## 隔离的 S3 协议集成测试

准备云端 Linux 环境后，在仓库根目录运行 `bash tests/integration/run.sh`。脚本创建独立的 Docker 网络命名空间，让 AWS 与 R2 形式的测试端点只解析到本轮的本地 HTTPS 服务。签名请求走工程中的 SDK，使用临时测试身份、临时 CA 和 Moto 测试数据。可将解包得到的 Linux 桌面程序路径作为第一个参数传入，以覆盖原生 WebView 与凭据存储流程。详细执行记录见 [STATUS.md](STATUS.md)。此验证与厂商托管服务的验收分别记录。

## AWS/R2 厂商实测

此项在具有授权凭据的云端验证环境运行。真实服务联调的入口、输入和请求上限见 [厂商验收入口](../tests/live/README.md)。使用已存在、内容已知的对象；普通 PR 继续运行无云凭据的测试。在验收记录中分别注明厂商、区域、对象大小、校验依据、实际操作、结果及请求标识。请勿记录对象内容、密钥、临时令牌或签名 URL。

有专用写入身份时，可用 `liveupload` 标签单独执行分片创建、单个 5 MiB 分片写入、服务端列出和中止检查。测试使用唯一 Key，完整对象不会发布。只读和写入两类命令、权限和清理条件见[厂商验收说明](../tests/live/README.md)。

桌面验收使用独立的测试用户配置。保存 AWS 或 R2 公开连接，再通过系统凭据库存储授权信息。验证分页、带特殊字符的 Key、下载后的字节摘要，以及缺少权限、密钥库上锁和远端对象变化时的可读错误。切换语言后继续观察同一任务，在关闭程序并重新打开后核对任务状态及本地文件。中断测试应记录已确认区间与恢复后实际发送的 Range 请求。单纯再次得到同样的文件无法证明任务从断点继续。

## 完整里程碑的真实云验证

以下矩阵覆盖 M1 至 M3 的完整目标。仅在对应功能已接入后执行。由授权人员提供专用测试桶、可清理的独立前缀及最小权限凭据。使用短期凭据或云端受控绑定，记录厂商、区域、授权范围与测试时段即可。保存日志或截图前执行脱敏。

| 提供方 | 重点核对 |
| --- | --- |
| AWS S3 | 区域和签名、分页令牌、分片上传、范围下载、服务端返回的校验字段；分片或加密对象的 ETag 语义。 |
| Cloudflare R2 | 账号端点、S3 兼容请求、分片与范围下载；单独覆盖定向建连、过期、手动 IP 错误、常规解析回退和证书不匹配。 |
| 阿里云 OSS | 原生 SDK 的区域端点、分页方式、列出和终止分片、请求标识与校验字段；按桶权限和实际 SDK 行为记录支持项。 |
| 火山引擎 TOS | 原生 SDK 的区域签名、续页标记、分片、范围下载、完整性校验和错误字段；验证与其他提供方一致的界面结果。 |
| 通用 S3 | 针对显式端点记录寻址方式和实测能力；按服务版本与配置记录兼容结果。 |

每个已接入提供方执行同一组基本操作：

1. 进入多个连接，浏览桶，创建多于测试页大小的对象。翻页核对集合，检查空前缀、Unicode 及包含字面点段或重复斜杠的 Key。使用安全选取的本地目标目录。
2. 上传空文件、小文件和跨多个分片的文件，独立计算源和下载文件的 SHA-256。检查信息、复制及删除的真实结果。覆盖只读账号、对象消失、过期凭据与厂商限流，验证中文解释、原始错误码、请求标识、重试次数与脱敏日志。
3. 在已确认部分分片后，分别断网、正常退出、终止进程和重启测试机。重开同一数据目录并核对恢复记录与服务端分片，检查完成后的字节数、摘要和实际重传范围。下载同样检查已写入区间。另测源文件被替换、远端版本改变、会话到期及完成请求响应丢失。
4. 并发运行跨账号、跨文件、跨分片的上下行任务，包含重试。分别记录每方向发送或接收字节、观察窗口与允许的突发量；切换全速、办公和自定义模式以及 UI 语言，核实总速率和状态连续性。
5. 对指定桶运行测速，分别触发时间上限、流量上限、取消及失败。检查远端测试对象和未完成会话；在清理中断后验证恢复清理。将测速与普通传输并行，核实共享的应用级限额。
6. 对 R2 分别检查原始端点名的签名、请求 Host、TLS SNI、证书校验和实际拨号目的 IP。使用错误证书及错误候选 IP 验证失败路径，再验证缓存过期和回退。确认另一个端点不受影响。
7. 删除本轮前缀下创建的对象，列举并终止本轮未完成会话。启用版本控制的桶还要处理本轮生成的版本及删除标记。记录遗留资源的可安全识别信息和清理结果。

基准可另行记录 rclone 版本、同桶同源样本、并发数与网络条件。性能对比独立于 S3S 的恢复正确性与数据一致性证明。

Linux 原生 CI 会先编译带 `s3integration` 标签的测试程序，再通过 `S3S_INTEGRATION_BINARY` 运行隔离的 Moto 协议和恢复测试。PR 流程不使用厂商账号。
